# Assumptions that a library entry takes where the specification does not speak

## Context

Tier 3 of the [library index's finding rule](../taxonomies/README.md#a-finding-has-a-tier-and-the-tier-fixes-the-timing) asks an entry to record the assumptions that the specification does not cover. It asks for them grouped under one item. This record is that item. Each entry adds its group to the list below, and the argued form stays in the entry's own doctrine.

**`standards-spec`, at [line 166](https://github.com/headwater-ai/headwater/blob/5fb9518/docs/taxonomies/standards-spec/doctrine.md#L166) of its doctrine.** Neither shelf declares a `layout`, because a layout has no form for a subdirectory per component and the tradition's files are `<component>/functional.md`. `volatility: stable` on `spec_layer` is the assumption that the `design-spec` entry recorded for `doc_type`. Whether an entry may declare an identifier scheme with no namespace has two live patterns in this library and no ruling. The two expectation windows are judgments rather than measurements.

## Obligation

Four questions stand behind the group, and each one is a place where the meta-schema has to speak eventually.

A shelf layout has no form for one subdirectory per component. Nothing states when `volatility: stable` is a claim that an entry may make about a facet it declares. The library runs two identifier-scheme patterns, one with a namespace and one without, and no ruling picks between them. An expectation window is a number that an entry invents, and no document says what evidence sets one.

## Discharge

This record discharges when each of the four has an answer in the specification. It discharges the other way when the library index states that an entry takes them as readings. A partial answer discharges nothing, because the tier rule makes this one item by timing rather than by subject.
