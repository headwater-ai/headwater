# The base ships one voice regime and a prospective document has none

## Context

The base package carries one voice regime, which is `voice.declarative`, and it forbids `future_intent`. A requirements document states what a product must do before the product exists, so it is prospective by definition.

The [`brd-prd` entry](../taxonomies/brd-prd/doctrine.md#findings) therefore declares `regimes.voice.prospective`, on the `narrative` precedent that the `design-spec` entry set. Its fixture corpus measures what `declarative` would have reported over the same prose: four extra findings across four of seven documents. The second finding at [line 165](https://github.com/headwater-ai/headwater/blob/5fb9518/docs/taxonomies/brd-prd/doctrine.md#L165) holds the run.

## Obligation

An adopter who takes the bare base has no voice regime under which a requirements document can say what a product must do. A corpus of requirements on the base reports its own tradition as a finding, four times in seven documents by the one measurement there is.

Two entries have now added a voice regime that the base does not carry. So the base carries one regime and the language needs at least two, and nothing states which ones belong in a minimal base. [Q3](../spec/09-decisions.md#q3--how-much-of-the-default-taxonomy-ships-in-the-box) is the ruling that made the base minimal, and it did not measure this case.

## Discharge

This record discharges when the base carries a prospective voice regime. It discharges the other way when a decision names the bundle that a prospective corpus takes. A ruling that every adopter writes their own regime discharges it too. The base then says so where an adopter meets the one regime it has.
