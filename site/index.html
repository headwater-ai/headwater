Open-source checks for documentation

Check documentation on every commit. AI agents get more tasks right.

Headwater is a command-line tool that checks your documentation on every commit, as tests check code. It reports each missing field, broken link and unclassified file, with the repair. On held-out tasks in Headwater's own repository, an AI agent with the documents and the engine passed 85% of sessions (56 of 66). With neither, it passed 20% (13 of 65). That is about 4 times as many tasks right. The check itself uses no language model.

01

What the measurements show

A campaign measured how often an AI agent completes a task in a governed repository, on tasks that no tuning change saw. Three results are gains clear of chance.

20% → 85%
of sessions passed, over all eleven actions: 13 of 65 in a repository with neither the documents nor the engine, and 56 of 66 with both
63% → 96%
of sessions passed on a refactor across files: 30 of 48 with the documents alone, and 46 of 48 with what headwater init ships
44% → 67%
of sessions passed on a change to code that a document governs: 21 of 48 with the documents alone, and 32 of 48 with what headwater init ships

Each rate is rounded to a whole percent from the counts beside it. The differences are 64.8, 33.3 and 22.9 percentage points, and the 95% interval of each lies above zero. The two gains over the documents alone are on the code actions, two of the eleven actions measured. 02

How it works

1 ·Declare what you keep

One versioned file lists the kinds of document you keep, the fields each must carry and the links it may declare.

shelves:
  decisions: docs/decisions/**
kinds:
  decision:
    purpose: rationale
    facets: [status, summary, last_verified]
    relations: [supersedes, governs, traces_to]

2 ·Authors link the documents

Each document states its kind and its links in its front matter. A link names its target by identifier, so a rename breaks nothing.

0002-deliver-at-least-once.md
supersedes ↓
↑ superseded_by
0001-store-attempts-in-postgres.md

3 ·The check finds what broke

A finding names the rule, the place and the repair. One command applies each repair that needs no judgment.

$ headwater check --fix
headwater: fixed docs/decisions/0001-store-attempts-in-postgres.md (1 patch)

4 ·Headwater generates the rest

Headwater writes the indexes, the site navigation and the instruction file an AI agent reads. A hand edit to one fails the build.

docs/spec/README.md ← generated
docs/interfaces/README.md ← generated
site navigation ← generated
agent instruction context ← generated
headwater generate --check

03

Compared with other tools

Authors declare how documents relate. No language model extracts it.

LeanCTXCompresses what a coding agent reads. It checks nothing.
TrustGraphA language model extracts a graph from your documents. Headwater checks the documents.
ValeChecks prose style. Headwater checks structure. Use both.
Plain lintersCheck lines in one file, not links between files.
Site generatorsPublish what you give them, correct or not.

What ships today

The engine runs, and this repository checks its own documentation with it on every commit. headwater init sets up a repository with the engine and with the skills, the hooks and the MCP server that an AI agent works through. That is the configuration behind the two code gains above. The evaluation states the result for each of the eleven actions, with its interval and the tasks it rests on.
