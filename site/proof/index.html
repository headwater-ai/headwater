03

What works, and what is unproven

Working. The engine runs. This repository checks its own documentation on every commit, and consumes its taxonomy as a pinned published package.

Measured. An earlier campaign found that the documents under docs/ have a large effect on whether an AI agent gives a sufficient answer. The additive campaign then measured eleven actions that an agent takes in a governed repository, on tasks that no tuning change saw. Compared with the documents alone, what headwater init ships helped on the two code actions. It showed no clear effect on most of the others, where the documents alone already let the agent succeed almost every time. Of the layers tuned one at a time, only the engine showed a gain. The evaluation states every figure, its interval and the probes it rests on.

Unproven. What Headwater ships made an agent worse at superseding a document, and the defect behind that is open. The skills, the hooks and the MCP server showed no gain clear of chance. Every session ran one model on this one repository, the code sessions had no compiler, and no experiment measured the quality of governance itself. Open work is on the milestones page.

Installing. v0.8.3 carries a static Linux x86_64 archive and a macOS arm64 archive, each with a checksum, and neither needs a Rust toolchain. cargo install headwater-cli --locked is the alternative. The install page has each route.

04

How to check this page yourself

The project measured itself here, which is the weakest form of evidence. You can repeat it: the repository is public, and sh tools/site/refresh-figures.sh --print runs the engine and prints each figure on this page.

Nobody has yet measured this engine on documentation that is not ours.

The source of this project is github.com/headwater-ai/headwater, under Apache-2.0. The engine, the taxonomy library and the corpus these pages describe are all in it.
