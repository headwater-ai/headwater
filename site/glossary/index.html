Glossary

fifteen terms, as this site uses them

This is not the full vocabulary. The specification carries a much longer glossary for someone already filing documents in this corpus. This page holds only the words that recur, more than once, across the pages you can already read from here — enough to keep reading without a second tab open.

Census

The count of every file under the corpus root, and what became of each one, produced before any check runs. A file is typed, untyped and reported as such, or excluded by a declared rule that states its reason — nothing is silently unaccounted for. The self-assessment publishes this repository's own census.

Check

A rule that reads a scoped view of the graph and reports findings. It reads no file itself, opens no socket, and reads no clock — everything it needs already arrived when the graph was built. How it works walks through what a check reports and how a repair gets applied.

Corpus

The documents themselves — the assertions on the shelves a taxonomy defines. A taxonomy is the terminology; a corpus is what gets written in it, the way a schema and the rows that fill it are two different things.

Facet

One named piece of metadata a document's front matter carries, such as its status, its summary, or the date it was last checked. A kind names which facets its documents must declare.

Finding

What a check reports: the rule that fired, the location, the repair, and the obligation the rule discharges. A finding is an error when the repair takes no judgment, and advisory when the repair is a rewrite a person has to make.

Front matter

The block at the top of a document that carries its facets and its relations to other documents. The engine parses it once per file and builds the typed graph from it.

Governs

The relation a document declares to state that it is the authority over a file or another document — for example, the decision record that governs each hand-built page of this site. A governs edge that names a path with no file behind it is itself a finding, which is what stops a governed page from being deleted without anyone noticing.

Graph

What the corpus is, once built: documents as typed nodes, and front-matter references between them as typed edges. Nothing stores the graph — every run rebuilds it from the documents themselves, and a cache only makes that rebuild cheap.

Kind

What a document permanently is. A kind names the facets a document of that kind must carry, the sections it must have, and the relations it may declare — a decision record and an obligation record are two different kinds, each with its own rules.

Obligation

A claim the system makes about itself, with the rule that verifies it named beside it. The obligation register reports each one as verified, gap, or unverifiable, and every gap names an owner rather than sitting unassigned.

Overlay

What an adopter's own repository adds on top of a shared taxonomy package — its namespace, any extra kinds it needs, its own phrasing. Customizing the taxonomy this way never means forking the engine that reads it.

Projection

Anything derived from the corpus rather than written by hand — an index, a navigation file, an exported graph. A projection that drifts from the documents it was built from fails the build rather than silently going stale.

Relation

A typed, declared link from one document to another, named in that document's front matter. Governs is one relation among several a kind may declare.

Shelf

A region of the directory tree that carries one purpose, and usually settles what kind a document placed on it is allowed to be.

Taxonomy

The schema itself — the shelves, kinds, facets and relations a corpus is checked against. It is versioned and shared, and it is separate from the documents it governs, the way a grammar is separate from what gets written in it.

More depth on any of this lives at how it works, which walks the same four steps — taxonomy, graph, checks, projections — with real output from this repository.
